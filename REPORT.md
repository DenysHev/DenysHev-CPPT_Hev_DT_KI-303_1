# Звіт до лабораторної роботи №5

## 1. Тема, номер і варіант

**Тема:** параметризоване сховище, винятки й CSV-експорт у Java-проєкті.
**Лабораторна робота:** №5.
**Варіант:** 4 — склад автозапчастин.
**ОС розробки:** macOS.
**Технології:** Java 21, Maven, JUnit 5, SpotBugs, GitHub Actions.

Номер варіанта та предметна область попередніх робіт збережені.

## 2. Мета роботи

Мета роботи — додати до наскрізного Java-продукту параметризоване сховище,
власний checked exception із ланцюгом причин, runtime-анотацію CSV-стовпців
та універсальний рефлексивний експорт і імпорт даних.

## 3. Стан до і після роботи

До роботи записи оброблялися лише в пам'яті. Після роботи додано:

- `Repository<T>` для типобезпечного зберігання;
- `SparePartRecord` для CSV-представлення варіанта 4;
- `CsvColumn` для опису назв стовпців одним елементом `String value()`;
- `CsvExporter` для універсального експорту та імпорту;
- `DataStorageException` для помилок збереження, формату та reflection;
- позитивні, граничні й негативні тести.

Поліморфна модель `SparePart`, Stream API-запити, CLI та попередній формат
звіту не змінені.

## 4. Параметризоване сховище

`Repository<T>` не використовує raw types. Метод `add` приймає лише `T`,
`find` приймає `Predicate<? super T>`, а `snapshot` повертає незмінний
знімок через `List.copyOf`. Пошук повертає `Optional<T>`, тому відсутність
запису не маскується значенням `null`.

Сховище не відкриває внутрішній список для зовнішньої модифікації. Додавання
`null` і передавання `null` як предиката відхиляються явно.

## 5. Модель варіанта 4 і CSV-контракт

`SparePartRecord` містить такі поля:

| Java-поле | Тип | CSV-назва |
|---|---|---|
| `article` | `String` | `артикул` |
| `name` | `String` | `назва` |
| `quantity` | `int` | `кількість` |
| `price` | `double` | `ціна` |
| `manufacturer` | `String` | `виробник` |

Артикул, назва та виробник не можуть бути порожніми. Кількість і ціна мають
бути невід'ємними, а ціна — скінченним числом. Усі поля позначені
`@CsvColumn`.

Експортер сортує поля за Java-іменем, тому детермінований заголовок має вигляд:

```text
артикул,виробник,назва,ціна,кількість
```

Приклад рядка з escaping:

```text
A-1,Bosch,"Фільтр, ""преміум""
новий",125.5,4
```

Контрольний приклад з п'ятьма записами зберігається у
[data/input.csv](/Users/denishev/repos/CPPT_LABS/data/input.csv).

## 6. Рефлексивний експортер та імпорт

`CsvExporter`:

1. знаходить анотовані поля класу та його суперкласів;
2. сортує їх за іменами Java-полів;
3. отримує назви стовпців з `@CsvColumn`;
4. перевіряє `trySetAccessible()` і читає значення приватних полів через reflection;
5. формує заголовок і рядки CSV;
6. читає CSV parser-ом станів та передає поля предметному parser-у.

Для порожнього списку клас передається окремо, тому заголовок створюється
навіть без першого об'єкта. Якщо анотованих полів немає, повертається
`DataStorageException`, а не порожній CSV.

Запис виконується через `BufferedWriter` і `Files.newBufferedWriter` з
явним `UTF_8`, `CREATE` та `TRUNCATE_EXISTING`. Читання виконується через
`Files.readString` з `UTF_8`.

Parser розрізняє кому та перенесення рядка всередині лапок і підтримує
подвоєння подвійних лапок. Таким чином, CSV читається як документ, а не як
набір фізичних рядків.

## 7. Помилки

| Рівень | Приклад | Реакція |
|---|---|---|
| Модель | порожній артикул, від'ємна кількість | `IllegalArgumentException` |
| CSV | неправильний заголовок, кількість полів або число | `DataStorageException` із `cause` |
| Файл | відсутній або недоступний шлях | `DataStorageException` із `IOException` |
| Reflection | немає анотованих полів або доступ заборонено | `DataStorageException` із `cause` |

Помилки не поглинаються порожнім результатом. Повідомлення містять операцію
або номер CSV-рядка, а першопричина доступна через `getCause`.

## 8. Збережена функціональність попередньої роботи

Попередня поліморфна модель `SparePart`, `OriginalPart`, `ReplacementPart`,
`PartKind`, Stream API-запити, CLI та звіт збережені. Попередній контрольний
CSV використовує формат:

```text
sku;name;stock;unitPrice;supplier
```

`InventoryStreamQueries` і далі реалізує:

- фільтрацію деталей із `stock < 10`;
- перетворення деталей на список артикулів;
- групування вартості запасу за виробником;
- `DoubleSummaryStatistics` для цін;
- top-N за ціною та назвою;
- пошук першого збігу через `Optional`.

Нове плоске представлення `SparePartRecord` не змінює цей попередній
контракт.

## 9. Тестування

Додано `RepositoryTest` і `CsvExporterTest`. Вони перевіряють:

- типобезпечне додавання, пошук і незмінність snapshot;
- runtime-анотацію та детермінований заголовок;
- коми, подвійні лапки й перенесення рядка;
- round-trip для `SparePartRecord`;
- порожній CSV із заголовком;
- неправильний заголовок, кількість полів і число;
- відсутній файл і збереження `cause`.

Збережено всі попередні тести. Команда `./mvnw -B test` проходить:
**60 тестів, 0 помилок, 0 пропущених тестів**.

Round-trip має вигляд:

```text
SparePartRecord → CSV → SparePartRecord
```

і підтверджує рівність початкових та відновлених об'єктів.

## 12. Порівняння підходів

Звичайний список не забезпечує єдиного типізованого API для додавання,
пошуку та отримання знімка. `Repository<T>` централізує ці операції та не
дозволяє зовнішньому коду змінити внутрішній стан.

Предметний `fromCsv` знає типи й правила валідації `SparePartRecord`.
Універсальний `CsvExporter` не містить назв класів або підтипів конкретного
варіанта: він використовує лише `@CsvColumn`, reflection та переданий
предметний parser.

## 14. Відповіді на контрольні питання

1. **Яку проблему розв'язує параметр типу в Repository<T>?** Він задає
   тип записів під час створення сховища та забезпечує перевірку типів
   компілятором без приведень.
2. **Чим параметризований клас відрізняється від raw type?**
   `Repository<SparePartRecord>` зберігає конкретний контракт типів, а raw
   `Repository` втрачає частину перевірок і може спричинити помилки під час
   виконання.
3. **Навіщо Predicate<? super T> у методі пошуку?** Такий wildcard
   дозволяє передати предикат, який приймає `T` або його супертип, без
   втрати типобезпеки.
4. **Чому all() має повертати незмінний знімок?** Зовнішній код не повинен
   змінювати внутрішній список сховища; копія також фіксує стан на момент
   виклику.
5. **Що таке checked exception і коли він доречний у цій роботі?** Це
   виняток, який компілятор змушує обробити або оголосити. У цій роботі
   `DataStorageException` доречний для помилок файлу, CSV і reflection.
6. **Для чого зберігати cause власного винятку?** Щоб додати зрозумілий
   контекст операції та не втратити первинну технічну причину.
7. **Чим Path і Files кращі за складання шляху рядком?** Вони дають
   платформонезалежні операції з файлами й коректно працюють із роздільниками
   шляхів на різних ОС.
8. **Чому кодування потрібно задавати і під час запису, і під час читання?**
   Явний UTF-8 гарантує однакове трактування українського тексту незалежно
   від системного кодування ОС.
9. **Що роблять @Retention(RUNTIME) і @Target(FIELD)?**
   `@Retention(RUNTIME)` залишає анотацію доступною reflection під час
   виконання, а `@Target(FIELD)` дозволяє застосовувати її лише до полів.
10. **Чому анотація не виконує експорт сама?** Анотація є лише метаданими;
    логіку пошуку полів, читання значень і формування CSV виконує
    `CsvExporter`.
11. **Чим getDeclaredFields() відрізняється від отримання публічних полів?**
    Він повертає поля, оголошені самим класом, зокрема приватні.
12. **Навіщо перевіряти trySetAccessible()?** Він показує, чи дозволено
    reflection доступ до приватного поля. Якщо повертає `false`, експортер
    повинен повідомити про помилку, а не приховати її.
13. **Чому порядок полів для CSV потрібно зробити детермінованим?**
    JVM не гарантує потрібний порядок reflection; сортування іменами робить
    заголовок, імпорт і тести відтворюваними.
14. **Чому split(",") не підходить для загального CSV?** Він розділяє кому
    всередині лапкового поля. Потрібен parser станів над усім текстом
    документа.
15. **Як екрануються кома, лапка й перенесення рядка?** Поле з такими
    символами оточується подвійними лапками, а внутрішня лапка замінюється
    на дві подвійні лапки.
16. **Чому порожній список потребує окремого параметра Class<T>?** Без
    першого об'єкта неможливо визначити поля для заголовка; клас передає цю
    метаінформацію незалежно від кількості записів.
17. **Чим універсальний експортер відрізняється від предметного fromCsv?**
    Універсальний експортер не містить назв `SparePartRecord` або його
    підтипів і працює з будь-яким класом, який має `@CsvColumn`.
18. **Які рівні помилок розрізняє програма?** Помилки моделі дають
    `IllegalArgumentException`; помилки формату, значення, файла та
    reflection обгортаються в `DataStorageException` із контекстом і cause.
19. **Що доводить тест round-trip?** Він підтверджує, що після послідовності
    запису CSV та імпорту відновлюються ті самі поля, порядок записів і
    спеціальні текстові значення.
20. **Чому виняток не можна поглинати порожнім catch?** Порожній catch
    приховує причину помилки та створює хибне враження про успішну операцію.
