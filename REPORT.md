# Звіт до лабораторної роботи №3

## 1. Тема, номер і варіант

Кросплатформні засоби програмування, лабораторна робота №3, варіант 4 —
**склад автозапчастин**. Розробка виконувалась на macOS, Java 21, Maven.

## 2. Мета роботи

Розширити модель ЛР2 абстрактним базовим типом, двома підтипами, `enum`,
поліморфною операцією та коректною рівністю об'єктів, не змінюючи зовнішній
CSV-контракт і попередні показники.

## 3. Стан до і після роботи

У ЛР2 всі записи створювалися одним конкретним класом. У ЛР3 `SparePart`
став абстрактним базовим класом, а конкретні записи представлені
`OriginalPart` і `ReplacementPart`. Додано категорію `PartKind`, метод
`warrantyCost()`, `equals/hashCode` і тести поліморфної моделі.

## 4. Базовий тип

`SparePart` зберігає спільні фінальні поля `sku`, `name`, `stock`,
`unitPrice`, `supplier`. Захищений конструктор перевіряє обов'язкові поля,
невід'ємний запас і скінченну невід'ємну ціну. Спільні аксесори та CSV
представлення не дублюються в підтипах.

Абстрактні методи `kind()` і `warrantyCost()` задають операції, які кожен
підтип реалізує самостійно. Спадкування обрано, бо обидва різновиди є
автозапчастинами та мають однакові інваріанти, але різну гарантійну політику.

## 5. Підтипи

`OriginalPart` реалізує гарантійну вартість як 20% від `stock * unitPrice`.
`ReplacementPart` використовує ставку 10%. Обидва класи перевизначають
абстрактні методи з `@Override`, але не дублюють базові поля та перевірки.

`SparePart.fromCsv` створює замінну деталь для артикулів `REP-`/`REPL-`, а
інші артикули, зокрема старі `SKU-`, створюють оригінальну деталь. Це зберігає
п'ять полів старого формату.

## 6. Enum

`PartKind` має значення `ORIGINAL` і `REPLACEMENT`. Метод `kind()` кожного
підтипу повертає відповідне значення, тому категорія є частиною моделі, а не
неформальним рядком.

## 7. equals і hashCode

Рівність визначається типом конкретного класу та всіма спільними полями.
Тому однакові дані в оригінальної та замінної деталі не роблять їх рівними:
поведінка і гарантійні правила різні. `hashCode` використовує той самий
критерій. Тести перевіряють `HashSet.contains`, однакові хеші рівних об'єктів
і відмінність підтипів.

## 8. Поліморфізм

`TaskMetrics.calculateWarrantyCost(List<SparePart>)` приймає колекцію
спільного типу та викликає `SparePart::warrantyCost`. Для вибору формули
немає центрального `if` або `switch`: Java динамічно викликає реалізацію
відповідного підтипу.

## 9. Тестування

Збережено попередні тести парсера, метрик і форматера. Додано
`PolymorphismTest`, який перевіряє:

- створення обох підтипів фабрикою;
- обидва значення `PartKind`;
- різні гарантійні формули;
- обробку різнорідної колекції через базовий тип;
- `equals/hashCode` у `HashSet`;
- нерівність об'єктів різних підтипів.

Також збережено позитивні, граничні та негативні перевірки ЛР2: нульові
значення, порожні поля, неправильну кількість полів, нечислові та від'ємні
значення, `NaN` та нескінченність.

## 10. Інфраструктура

```text
./mvnw -B test
./mvnw -B clean verify
./mvnw -B package
java -jar target/cppt-labs.jar --input data/input.csv
```

Maven використовує Java 21, JUnit 5, SpotBugs і Shade Plugin. Workflow
`.github/workflows/ci.yml` запускає `verify` на Ubuntu, Windows і macOS та
публікує виконуваний JAR.

## 11. GitHub Issues і Pull Request

Зміни виконані в репозиторії як продовження історії ЛР2. Відповідність
«зміна → перевірка»:

| Зміна | Перевірка |
|---|---|
| Ієрархія деталей і `PartKind` | `PolymorphismTest` |
| Поліморфна гарантійна вартість | тест `metricsCallsPolymorphicMethodThroughBaseType` |
| Сумісність ЛР2 | усі попередні 37 тестів |
| Інфраструктура | `mvn clean verify`, CI matrix |

Посилання на конкретні Issue/PR додаються після публікації роботи в GitHub.

## 12. Порівняння поведінки

CSV із п'ятьма полями, аргументи CLI, чотири показники та формат основної
частини звіту залишилися сумісними з ЛР2. Доданий рядок гарантійної вартості
не змінює попередні значення. Артикули `SKU-` автоматично обробляються як
оригінальні, тому старий `data/input.csv` не потребує нового поля.

## 13. Академічна доброчесність

Під час роботи використано AI-асистента Copilot SDK у VS Code для аналізу
методички, проєктування ієрархії, підготовки тестів і перевірки Maven-збірки.
Прийняті пропозиції перевірено читанням коду, тестами та `verify`; остаточні
рішення щодо назв, ставок гарантії та сумісності формату прийняті автором.
Автор має пояснити базовий клас, кожен підтип, фабрику, рівність і
поліморфний виклик.

## 14. Відповіді на контрольні питання

1. **Базовий клас** містить поля та інваріанти, спільні для всіх деталей.
2. **Абстрактні методи** змушують кожен підтип визначити власну поведінку.
3. **Поліморфізм** дозволяє викликати `warrantyCost()` через `SparePart`.
4. **Enum** безпечно представляє фіксований набір категорій.
5. **`equals/hashCode`** використовують однакові поля та враховують підтип.
6. **HashSet** знаходить рівний об'єкт, бо його хеш і рівність узгоджені.
7. **Центральний switch** за підтипом порушив би відкритість моделі для
   додавання нових типів; формула належить самому підтипу.
8. **Незмінність** захищає об'єкт від зміни після вставки в `HashSet`.
9. **CSV-сумісність** збережена через визначення категорії за артикулом.
10. **Тести** перевіряють і модель, і колекцію спільного типу, і стару
    поведінку звіту.

## 15. Висновки

Модель складу розширено без дублювання спільного стану та без втрати
сумісності ЛР2. Ієрархія `SparePart` є основою для наступної роботи:
різнорідну колекцію можна безпечно обробляти потоками та складеними
запитами.
